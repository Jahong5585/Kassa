# Android 0.2.93 — один вход владельца

После нового OIDC-входа единственный магазин владельца открывается автоматически с созданием серверной сессии владельца, без повторного браузерного входа и выбора той же личности. При нескольких магазинах показывается список всех доступных магазинов; сохранённый магазин не скрывает остальные. В настройках владельца доступен пункт «Магазины и кассы», а кассы выбранного магазина доступны через «Сотрудники и кассы».

Если GET /v1/me/stores недоступен, приложение сохраняет вход и предлагает повторить загрузку. Поля UUID и подмена списка тестовыми магазинами с этого экрана удалены. Для возврата от сотрудника к владельцу на общем устройстве проверка владельца сохраняется.

## Серверная приёмка

Список нельзя восстановить только изменением интерфейса, если рабочий API действительно не обслуживает GET /v1/me/stores. Этот маршрут присутствует в проверенной серверной ветке feature/register-device-bindings (4deb0987e0671e9319ee4155fccb3f9814b37c3f) и вызывает OperatorService.ListMyStores. Он использует текущий OIDC subject и возвращает активные назначения; UUID пользователя не требуется. Проверить развёрнутую версию, маршрутизацию reverse proxy и ответ с токеном реального владельца. Пустой корректный список возвращается как 200 с items: [], отсутствие маршрута не должно маскироваться тестовыми данными.

Список всех касс выбранного магазина получает StoreManagementApi.registers с пагинацией. Кассы другого владельца не должны появляться. Просмотр касс не требует ручного ключа; первая привязка выбранной кассы к телефону использует механизм device-bindings из 0.2.92.

Проверка реального аккаунта и развёртывания сервера в этой сессии недоступна: MyGit сообщает, что tunnel-client не подключён. Автоматические клиентские тесты используют контролируемые HTTP-ответы, а не production.
