# Отчёт: привязка устройства к существующей кассе

Дата: 2026-11-19  
Ветка: `feature/register-device-bindings`  
Коммит кода: `bec969e`  
Базовый production-коммит: `2a51114`

## Выполнено

- Добавлена отдельная отзываемая учётная запись устройства для существующей кассы. Общий register key не ротируется и не раскрывается.
- Новый непрозрачный токен возвращается один раз; в PostgreSQL хранится только SHA-256 digest.
- Привязка ограничена организацией, магазином, кассой, `deviceId` установки и OIDC host владельца.
- При входе назначенного кассира сервер автоматически возвращает `registerId` привязанной кассы.
- Добавлен список активных касс, назначенных фактически вошедшему сотруднику.
- Кассовые операции принимают новый `X-Register-Device-Token` либо старый `X-Register-Key` на переходный период.
- На каждом кассовом запросе проверяются операторская сессия, фактический сотрудник, роль `cashier`, организация, магазин, активность кассы, назначение кассира, устройство и credential кассы.
- Поддержаны несколько кассиров на одной кассе и несколько ролей сотрудника.
- Выход оператора не удаляет привязку устройства. Следующий сотрудник входит своим кодом и использует ту же кассу.
- Отзыв привязки применяется немедленно. Отключение кассы отзывает её device bindings. Удаление назначения кассира сразу блокирует кассовые действия.
- Перенос устройства на другую кассу запрещён, пока на старой кассе открыта смена.
- Существующие кассы, их UUID, register key digests, назначения, смены, продажи и аудит не изменяются миграцией.

## Новые маршруты

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| `POST` | `/v1/stores/{storeId}/registers/{registerId}/device-bindings` | Владелец привязывает текущее устройство, токен выдаётся один раз |
| `GET` | `/v1/stores/{storeId}/registers/{registerId}/device-bindings` | Владелец получает список привязок без секретов |
| `POST` | `/v1/stores/{storeId}/registers/{registerId}/device-bindings/{bindingId}/revoke` | Владелец отзывает привязку |
| `GET` | `/v1/operator-sessions/current/registers` | Текущий сотрудник получает назначенные активные кассы |

`POST /v1/stores/{storeId}/operator-sessions` теперь дополнительно возвращает nullable `registerId`. Все старые поля сохранены.

Кассовые маршруты новых клиентов используют:

```http
Authorization: Bearer <oidc_access_token>
X-Operator-Session: <operator_session_token>
X-Active-Role: cashier
X-Register-Id: <register_uuid>
X-Register-Device-Token: <скрыто>
```

Старый Windows-клиент продолжает использовать `X-Register-Key` вместо `X-Register-Device-Token`.
