# Серверный релиз для Android 0.2.100 и Desktop 0.8.18

База изменений: `35321fe`. Рабочее развёртывание этим изменением не выполняется.

## Изменённые маршруты

- `GET /v1/stores/{storeId}/finance/expenses?from=&to=&category=&includeReversed=&offset=` — список расходов.
- `GET /v1/stores/{storeId}/finance/expenses/{id}` — одна запись расхода.
- `POST /v1/stores/{storeId}/finance/expenses` — создание расхода. `operationId` является ключом идемпотентности.
- `POST /v1/stores/{storeId}/finance/expenses/{id}/reverse` — сторнирование. `operationId` тела является ключом идемпотентности сторнирования.
- `GET /v1/reports/stores/{storeId}/finance?from=&to=` — продажи, себестоимость, валовая прибыль, складские потери, операционные расходы, чистая прибыль, оплаты и задолженность поставщикам.
- `GET /v1/reports/stores/{storeId}/finance/csv?from=&to=` — те же финансовые итоги в CSV.
- `GET /v1/catalog/snapshot` — активный оценённый каталог текущей кассы для предварительной загрузки Desktop. Обычные `/v1/catalog/search` и `/v1/catalog/barcodes/{barcode}` сохранены.
- `GET /v1/expiry/cashier`, `GET /v1/stores/{storeId}/stock/expiry`, `GET /v1/reports/stores/{storeId}/stock-expiry` и `/csv` принимают необязательный `category`. Без него JSON и CSV сохраняют прежнее поведение; схема CSV не меняется.

Все бизнес-маршруты сохраняют действующую проверку Bearer, операторской сессии, активной роли и кассового устройства. `Auth:RequireOperatorSession` не меняется. OIDC + PKCE Desktop, мобильная авторизация, `X-Register-Key` и `X-Register-Device-Token` не изменены.

## Финансовая формула

`netProfit = grossProfit - inventoryExpenses - operatingExpenses`.

Закупочная стоимость не вычитается второй раз: она уже входит в `costOfGoodsSold`. При неполной оценке себестоимости или складских потерь `netProfit` остаётся `null`. Сторнированные расходы не входят в итог.

## Миграция

- Вверх: `db/042_operating_expenses.sql`.
- Вниз: `db/rollback/042_operating_expenses.down.sql`.

Миграция создаёт только `operating_expenses`, два индекса и минимальные права роли `kasa_api`. Существующие таблицы и данные не изменяются.

## Порядок развёртывания после приёмки

1. Зафиксировать SHA принятого коммита и образ предыдущего API.
2. Создать PostgreSQL backup и проверить его восстановлением в отдельную PostgreSQL 17.
3. Остановить публикацию новых образов и применить `db/042_operating_expenses.sql` от владельца схемы с `ON_ERROR_STOP=1`.
4. Проверить наличие таблицы, индексов и прав `kasa_api`.
5. Собрать и развернуть только API из принятого коммита. Не менять Keycloak, PostgreSQL volume, Caddy и клиентские параметры.
6. Оставить действующее значение `Auth:RequireOperatorSession` без изменения.
7. Проверить `/health/live`, `/health/ready`, анонимный отказ на новых бизнес-маршрутах, авторизованные expenses/finance/snapshot и старые barcode/shift/sale маршруты.
8. Проверить Android 0.2.100 и установленный Desktop 0.8.18 на отдельном тестовом магазине.

## Откат

Предпочтительный откат API: вернуть сохранённый предыдущий образ, оставив миграцию `042` в базе. Старая версия API не использует новую таблицу, а записи расходов сохранятся для повторного выпуска.

Откат схемы допустим только после резервной копии и подтверждения, что данные расходов можно удалить. Выполнить `db/rollback/042_operating_expenses.down.sql`; он удаляет таблицу расходов. Затем проверить старый API и основные продажи/смены. При любой ошибке восстановить проверенную резервную копию.
