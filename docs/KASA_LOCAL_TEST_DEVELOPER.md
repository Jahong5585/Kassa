# Локальный тестовый разработчик платформы

Контур предназначен только для разработки на одном Windows-компьютере. Он не заменяет рабочий OIDC/FIDO2/USB-вход и не должен публиковаться через прокси или туннель.

## Первичная настройка

Запустите PowerShell без повышения прав из корня репозитория на диске D:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\deploy\Initialize-LocalTest.ps1
```

Сценарий создаёт игнорируемый файл `.env.local-test`, поднимает PostgreSQL 17 на `127.0.0.1:55435`, применяет миграции `001`–`035`, записывает в `platform_staff` активного `developer-test` с правами чтения и изменения, публикует API и запускает его на `http://127.0.0.1:3510/`. В базе хранится PBKDF2-SHA256-хеш, а не пароль.

## Управление

```powershell
.\deploy\Manage-LocalTest.ps1 Status
.\deploy\Manage-LocalTest.ps1 Start
.\deploy\Manage-LocalTest.ps1 Restart
.\deploy\Manage-LocalTest.ps1 Stop
```

Проверка режима:

```powershell
Invoke-RestMethod http://127.0.0.1:3510/development/platform/status
Invoke-RestMethod http://127.0.0.1:3510/health/live
```

## Windows-клиент

1. Запустите локальный API.
2. Откройте Kassa Desktop. Кнопка «Платформа · Тестовый вход разработчика» появляется только после успешной проверки Development-статуса локального API.
3. Укажите `http://127.0.0.1:3510/`, логин `developer-test` и выданный локально пароль.
4. После входа откроется раздел «Платформа». В нём доступны просмотр, создание и переименование только тестовых магазинов.

Пароль не сохраняется клиентом. Токен живёт 30 минут, refresh token не выдаётся. Организации и магазины, созданные этим маршрутом, получают `is_test=true`; триггер базы запрещает смешивать тестовую организацию с рабочим магазином.

## Защитные условия

- `Auth:AllowLocalTestDeveloper=true` разрешён только в `Development`.
- `ASPNETCORE_URLS` должен содержать только явный `http://127.0.0.1:<порт>`; `localhost`, `0.0.0.0`, LAN-IP и wildcard отклоняются.
- Endpoint входа дополнительно проверяет фактический loopback-адрес клиента и имеет лимит пять запросов в минуту на IP.
- Локальные JWT подписываются отдельным ключом. Обычный Development/OIDC-токен не может получить локальный признак.
- Вне локального режима операции платформы требуют настроенный `acr` FIDO2/WebAuthn и `usb_key_verified=true`.
- `.env.local-test`, JWT-ключи и пароль не должны попадать в Git, логи, снимки экрана или публичные отчёты.
