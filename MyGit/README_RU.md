# MyGit — личный GitHub без облачной квоты на сборки

**Состояние:** подготовленный, но НЕ запущенный пакет. На вашем компьютере ещё нужно выполнить установку. В комплекте нет самого приложения Forgejo: Docker скачает официальный образ при запуске.

## Почему Forgejo
- Бесплатный собственный Git-сервер (проекты, история кода, ветки, сравнения, Issues, релизы, API).
- Приватные репозитории по умолчанию, регистрация других людей запрещена.
- PostgreSQL 16 (отдельно, без открытого порта).
- Официальная LTS-версия Forgejo **15.0.11** (поддерживается до 15 июля 2027).
- Код и БД в постоянных Docker volumes. Бэкап с остановкой для согласованности.
- Возможна локальная сборка APK через **дополнительно установленный** Forgejo Runner.

## Требования

- Windows 10/11 + Docker Desktop + WSL2, **или** Linux + Docker Engine + Docker Compose.
- Docker Desktop официально **не поддерживается на Windows Server**. Для Windows Server выбирайте отдельную Linux VM/хост с Docker Engine.
- Минимум ориентировочно 2 ядра, 4 ГБ свободной RAM, 10–20 ГБ свободного диска для Git без CI; для сборки Flutter на отдельной машине потребуется больше RAM/SSD.
- Доступ к Интернету на первый запуск для скачивания Docker образов.

## Быстрая установка — Windows 10/11

1. Установите и откройте Docker Desktop; включите Linux containers / WSL2.
2. Распакуйте архив MyGit в отдельную папку (например `D:\MyGit`).
3. Откройте PowerShell в папке MyGit и запустите:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\INSTALL_WINDOWS.ps1
```

4. Откройте **http://localhost:3020/** на том же компьютере.
5. На первом экране настройки: база **PostgreSQL**, хост `database:5432`, имя БД `forgejo`, пользователь `forgejo` (если поля уже заполнены — не меняйте). Пароль задаётся из `.env` автоматически; если мастер просит пароль, прочитайте `DB_PASSWORD` локально в `.env` и не пересылайте его.
6. **Обязательно раскройте «Administrator Account Settings» и создайте административную учётную запись** с уникальным сильным паролем. Саморегистрация сразу отключена.
7. После входа включите 2FA в настройках аккаунта. Создайте первый Private-репозиторий (например `Kassa`).

## Быстрая установка — Ubuntu / Linux

```bash
cd /path/to/MyGit
chmod +x scripts/*.sh
./scripts/INSTALL_LINUX.sh
```

Затем выполните шаги 4–7 из Windows инструкции. Если сервер удалённый, открывать его нужно через безопасный SSH-туннель, а не открытый порт 3020:

```bash
ssh -L 3020:127.0.0.1:3020 user@your-linux-server
```

В браузере локального ПК откройте `http://localhost:3020/`.

## Команды управления

```bash
docker compose ps                 # статус
docker compose logs -f forgejo   # ошибки и запуск
docker compose stop              # остановить
docker compose up -d             # запустить
```

## Резервное копирование

Windows:
```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\BACKUP_WINDOWS.ps1
```

Linux:
```bash
./scripts/BACKUP_LINUX.sh
```

Архив сохраняется в `backups/` и включает данные, БД и `.env` с секретами. **Его необходимо шифровать** перед переносом на внешнее хранилище. Для надёжности делайте резервные копии на отдельном диске/компьютере, проверяйте восстановление. НЕ используйте `docker compose down -v` — это удаляет тома с данными!

### Восстановление бэкапа (после проверки на тестовой машине)

1. Заархивируйте текущие данные, чтобы иметь точку возврата.
2. Остановите MyGit: `docker compose down` (без `-v`).
3. Проверьте архив: `tar -tzf backups/mygit-....tar.gz`.
4. Распакуйте в именованные тома `mygit_forgejo_data`, `mygit_forgejo_config`, `mygit_postgres_data` через временный Alpine-контейнер, сохранив пути `forgejo_data/`, `forgejo_config/`, `postgres_data/`. Полное восстановление **перезаписывает существующие данные** и должно выполняться только после проверки копии.
5. Верните также `.env` и `docker-compose.yml`, затем `docker compose up -d`.

## Загрузка существующего Git-проекта

1. Создайте пустой приватный репозиторий в MyGit.
2. В папке существующего локального проекта выполните (замените `USER` и имя репозитория):

```bash
git remote add mygit http://localhost:3020/USER/Kassa.git
git push -u mygit main
```

Если ветка проекта не `main`, подставьте её имя. При доступе по HTTPS используйте персональный токен вместо пароля и не сохраняйте токен в скриптах. Для нового репозитория можно скачать `git clone` прямо из браузерного интерфейса.

**ВАЖНО:** `localhost` работает только на самом сервере. Чтобы подключаться с ноутбука/телефона, сначала настройте частную сеть или HTTPS, а затем замените `MYGIT_ROOT_URL` в `.env` на фактический HTTPS адрес и выполните `docker compose up -d`. Не открывайте нешифрованный HTTP-порт в Интернет.

## Безопасный удалённый доступ

Рекомендуется Tailscale: установите на сервер и свои устройства, откройте Forgejo по защищённому HTTPS через Tailscale Serve, оставляя Docker привязанным к 127.0.0.1. Настраивать Tailscale Serve и HTTPS нужно отдельно. Не используйте внешний `0.0.0.0:3020` без TLS/reverse-proxy и дополнительных мер безопасности.

Если потребуется публичный домен вроде `git.ваш-домен`, настройте DNS, HTTPS обратный прокси (Caddy/Nginx), а также резервирование и фильтрацию доступа отдельно. В комплекте публичный вход намеренно отключён; он никак не влияет на работающий сервер Kassa.

## Автоматическая сборка APK

Forgejo Actions встроены в сервер, но **не выполняют команды без Runner**. Runner — отдельная программа на отдельной машине / изолированной VM; именно она тратит процессор и оперативную память, а не минуты GitHub.

1. Разверните отдельную Linux VM/ПК для Runner, а не сам рабочий сервер Kassa.
2. Создайте Runner для конкретного репозитория через Repository Settings -> Actions -> Runners, настройте безопасную изолированную среду.
3. Подготовьте Flutter SDK, Android SDK и JDK в runner образе / VM и зарегистрируйте метку `flutter-android`.
4. Перенесите `examples/flutter/.forgejo/workflows/build-apk.yml` в репозиторий Flutter по пути `.forgejo/workflows/build-apk.yml`.
5. При push в main запускается сборка **debug APK**, результат должен появиться в Actions -> Artifacts после успешного выполнения. Для production подписанного APK нужен отдельный безопасный процесс подписи.

**Шаблон workflow подготовлен, но не проверен на вашей конкретной Flutter-проектной базе и Runner.** Для готовых исходников может потребоваться адаптировать версии SDK, flavor и команды сборки.

## Ограничения

- Нет облачной квоты GitHub Actions на сборки, но физический диск, сеть, CPU и RAM ограничены.
- Сервис не отменяет ограничения ChatGPT/Codex по количеству ИИ-запросов.
- Облачная интеграция Codex может требовать GitHub: доступ к личному Forgejo нужно проверять отдельно. Git-клиенты и локальные агенты обычно работают по стандартному Git HTTP(S).
- Этот пакет не является резервной копией ваших старых репозиториев. Их нужно перенести отдельно.

Дополнительный модуль находится в каталоге [`mcp-plugin/`](mcp-plugin/README_RU.md). По умолчанию он работает только на чтение и прослушивает `127.0.0.1:3030/mcp`. Необходим отдельный токен Forgejo, Python 3.11+ и безопасный туннель для подключения ChatGPT. Модуль подготовлен, но ещё не установлен на пользовательском сервере.
