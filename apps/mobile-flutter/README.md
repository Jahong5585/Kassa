# Касса для Android

Flutter 3.44.0, Android SDK 36. Стендовый APK 0.2.5 использует пакет `uz.qrspace.kassa.mobile.multirolepilot` и тестовую подпись. На телефоне отображается как «Касса · Роли 0.2.5».

## Сборка

```sh
flutter pub get
flutter analyze
flutter test
flutter build apk --release --target-platform android-arm64 --split-per-abi
```

## Проверка на телефоне

1. Нажмите «Войти». Для проверки кассы войдите как `test-cashier`. На новом устройстве введите выданный ключ через «Ключ кассы».
2. В правом верхнем углу нажмите кнопку с названием текущей роли. Меню получает назначенные роли через `GET /v1/me/roles?storeId=...`. Текущая роль отмечена галочкой. При переключении повторный вход не нужен.
3. Для проверки администратора выйдите из кассы и войдите как `test-admin` с TOTP. Если сервер назначил роль приёмщика, пункт «Приёмщик» появится в том же меню.
4. Для проверки без сети используйте «Учебный режим». В нём доступны «Кассир» и «Приёмщик».

Вход использует открытый клиент `kasa-flutter`, Authorization Code и PKCE. Адрес возврата `uz.qrspace.kassa:/oauth2redirect`. Токены хранятся в памяти процесса, ключ кассы вводится на устройстве и хранится в защищённом хранилище Android. Пароли, TOTP и ключи кассы в APK не включаются. В режиме сервера приложение обращается только к настроенной тестовой точке и её кассе. Окончательные права определяет API.

Клиент передаёт выбранную рабочую роль в заголовке `X-Active-Role`. Для полной работы нескольких ролей нужен API из ветки `codex/android-multi-role` с миграциями до `029_staff_roles.sql` включительно. При пустом HTTP 404 от сервера без маршрута списка ролей приложение использует проверки из предыдущего пилота. Для кассовых операций по-прежнему нужны привязка и ключ кассы, для административных — права магазина и MFA.

Черновик накладной сохраняется на устройстве. Отправка файла и проведение накладной администратором остаются следующей доработкой.
