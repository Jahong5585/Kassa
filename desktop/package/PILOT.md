# Касса минимаркета · приёмка пилота 0.5.8

## Установка

1. На выделенном пилотном ПК откройте архив и запустите KassaSetup.exe. Установка выполняется для текущего пользователя. Запустите Kassa Minimarket из меню «Пуск».
2. Для переносного запуска откройте portable/KasaDesktop.exe. Windows x64, .NET Framework 4.8 и Microsoft Edge WebView2 Runtime необходимы в обоих вариантах.
3. В «Настройках» выберите «Русский» или «O‘zbekcha». Переключение перезагружает интерфейс и завершает сеансы стенда. Сохранённые данные остаются в профиле Windows.
4. Сборка пилота поставляется без подписи издателя. Перед распространением используйте сертификат владельца и инструкции в разделе «Подпись». На пилотном ПК соблюдайте действующую политику установки.

## Обновление и откат

1. До обновления завершите расчёты, проверьте все ожидающие операции и закройте смену. Сохраните предыдущий архив, копию KasaPilot.json и закрытую копию папки %LOCALAPPDATA%\KasaDesktop для восстановления под той же учётной записью Windows. Ограничьте доступ к копиям.
2. Проверьте SHA-256 файлов по SHA256SUMS.txt. Для подписанного выпуска дополнительно проверьте подпись по инструкции ниже. Полностью закройте кассу и запустите установщик в прежнюю папку под тем же пользователем. Переносную версию распакуйте в новую папку и перенесите туда KasaPilot.json.
3. После обновления проверьте версию, вход, текущую смену и учебную печать. При отказе запуска сохраните текущую папку данных и журналы для диагностики. Для возврата к предыдущей сборке переустановите её в ту же папку или запустите прежнюю переносную версию.
4. Перед откатом снимите действующие уценки, отложите этикетки WPL и LOT и выключите акции 2+1, завершите или отмените активные отложенные чеки, сверяйте операции до исчезновения ожидания и закройте смену. Журнал с весовой этикеткой использует формат 5, с уценкой — формат 4, с действующей акцией 2+1 — формат 3, отложенный чек без этих настроек — формат 2. Сверку ведите в версии, которая открывает исходный журнал. Копия локальных данных содержит состояние на момент копирования. Перед её применением проверьте последующие операции на сервере.

## Обновление сервера для 0.5.8

Перед обновлением касс на стенде примените серверный патч и миграцию 028 по инструкции SERVER_UPDATE.md. Проверьте версию API и обновите все кассы, прежде чем включать уценку и использовать этикетки LOT и WPL.

## Проверка быстрых товаров

1. На стенде создайте штучный товар без штрихкода, задайте цену и остаток. Для яиц выберите единицу продажи в карточке. Отдельное яйцо и упаковка из десяти яиц ведутся разными позициями.
2. Откройте смену, найдите товар по названию и нажмите «Закрепить». Одно нажатие на кнопку должно добавить одну штуку. Для корректировки используйте «−» и «+» в строке чека. «−» при одной штуке убирает строку, «+» останавливается на остатке партии. Для большого количества введите число в поле между кнопками.
3. Проверьте переоценку и товар с несколькими партиями. Кнопка должна применить свежую цену и открывать выбор партии при необходимости. После перезапуска и подключения к той же кассе проверьте сохранение панели и удаление кнопки через «Настроить».

## Подключение чекового USB-принтера

В «Настройки → Проверка оборудования» нажмите «Найти USB-принтеры и драйверы». Проверьте распознавание до установки, выбор модели, скачивание и установку вне расчёта. После завершения обновите список кнопкой «Проверить принтеры» и распечатайте учебный чек. Настройка размещения пакетов приведена в PRINTER_DRIVERS.md.

## Проверка весовой этикетки T-04

1. На учебном API установите цену весового товара 16 400 сум за кг. В «Приёмка и склад → Остатки» выберите годную партию, нажмите «Весовая этикетка» и введите вес нетто 0,375 кг. Скопируйте WPL-код и сумму 6 150 сум. Для теста введите код с клавиатуры и нажмите Enter. Для проверки печати внесите этот код, товар, вес и сумму в макет вашего принтера.
2. Поменяйте цену на 18 000 сум за кг. Сканируйте старую этикетку. На экране должны быть 6 150 сум с этикетки и 6 750 сум по текущей цене. Корзина и остаток должны остаться прежними. Пилотное правило направляет кассира к администратору за заменой этикетки. Уберите старую этикетку с упаковки.
3. Создайте новый код по актуальной цене. Проведите продажу. В чеке должен быть вес 0,375 кг, остаток должен уменьшиться на тот же вес. Повторно предъявленный код должен получить отказ. Для разных упаковок одной партии используйте отдельные чеки.
4. Для приёмки существующих этикеток приложите несколько образцов с видимым весом, суммой, штрихкодом и моделью устройства. Согласуйте источник веса, расшифровку кода и действие кассира при конфликте.

## Профиль входа и роли

1. Зарегистрируйте у провайдера публичный клиент для настольного приложения. Разрешите Authorization Code с PKCE S256 и loopback redirect по адресу http://127.0.0.1/oauth/callback с динамическим портом. Клиентский секрет для приложения не нужен.
2. Скопируйте KasaPilot.example.json рядом с KasaDesktop.exe в KasaPilot.json. Укажите HTTPS-адрес API, точный issuer из discovery, ID клиента, scope с openid, ID магазина и, для кассира, ID кассы. Опциональный resource передавайте только при поддержке у провайдера. Настройте аудиторию токена в соответствии с конфигурацией API.
3. Свяжите пользователей провайдера с сотрудниками и ролями в API. Зарегистрируйте кассу и назначьте её кассирам. Настройте MFA администратора на провайдере и требование ACR в API. При необходимости заполните adminAcrValues.
4. Кассир выбирает подключение к стенду в «Настройках» и вводит ключ кассы. Приёмщик и администратор подключаются со своего рабочего места. Ввод учётных данных происходит в системном браузере. При подтверждении возврата администратор проходит отдельный вход. API проверяет токен, сотрудника, роль и привязку к кассе или магазину.
5. Приложение использует access token в памяти сеанса. Проверку подписи, издателя, аудитории и полномочий выполняет API. После истечения токена нажмите «Обновить сеанс». Отложенные операции можно восстановить после входа тем же пользователем. Режим ручного ввода короткоживущего токена доступен для учебного стенда, когда файл профиля отсутствует.
6. Чтобы отозвать доступ, деактивируйте сотрудника или кассу на сервере и отзовите доступ у провайдера по его регламенту. Затем проверьте отказ уже открытой сессии и отсутствие доступа к незавершённым операциям при входе под другим сотрудником.

## Сверка после потери ответа

1. Оставьте исходную корзину и её запись в ожидании. После восстановления связи нажмите «Проверить статус». После перезапуска сначала войдите под той же учётной записью на той же кассе и стенде.
2. Если операция найдена, сверьте сумму, состав и номер. Откройте чек из истории или повторите печать. При ошибке принтера сохранённая продажа остаётся в истории.
3. Если подтверждение не найдено и программа предлагает повтор, нажмите «Повторить ту же операцию». Клиент отправит исходное тело и исходный ID. При ошибке доступа или конфликте передайте администратору ID, время и код ошибки. Сверьте операцию по серверному журналу перед новым расчётом.
4. Для отложенного чека программа сначала проверяет сохранённый ID. После подтверждения он появляется в списке «Отложенные чеки». Проверка цены выполняется при восстановлении и перед оплатой.

## Результаты локальных испытаний 0.5.1

- На изолированном стенде применены 25 миграций PostgreSQL 17.11. Серверный сценарий прошёл 30 групп проверок с учебными данными двух организаций. В числе проверок разграничение прав, конкурирующие продажи, возвраты, накладные, остатки, отчёты и отзыв доступа.
- Экран кассы в Chromium подключили к этому API по HTTPS через тестовый адаптер настольного моста. Смоделировали отсутствие связи перед оплатой и потерю ответа после записи продажи. В первом случае диалог оставался закрытым и корзина сохранилась. Во втором экран восстановил чек по исходному ID, а сервер зарегистрировал одну продажу и одно списание.
- Учебный дамп восстановлен в отдельную базу. Контрольные значения продажи, смены, складского движения, остатка и аудита совпали.
- В этих испытаниях использовались локальный сертификат, тестовые JWT и имитатор проверки вложений. Запуск установщика, WebView2, устройства и MFA реального провайдера входят в очную приёмку по протоколу ниже.

## Протокол на реальном стенде

Запишите дату, версию клиента и API, версию Windows, магазин, модель и версию драйвера каждого устройства, исполнителя, итог и ссылку на обезличенное свидетельство. Используйте две тестовые организации и учебные суммы.

| ID | Действие | Ожидаемый результат |
| --- | --- | --- |
| P01 | Установить, обновить предыдущую версию и открыть меню «Пуск» | Программа запускается, данные кассы сохраняются. Обновление выполняется при закрытом приложении |
| P02 | Войти кассиром и проверить действия приёмщика и администратора | API допускает только назначенные операции и магазин |
| P03 | Войти администратором без нужного ACR, затем с требуемым MFA | Без требуемого MFA сервер отклоняет действие. С MFA действие доступно |
| P04 | Попытаться использовать кассу, склад или ID операции другой организации | Интерфейс и прямой запрос API не раскрывают чужие данные |
| P05 | В «Настройках» проверить сканер в режиме USB HID с суффиксом Enter, затем отсканировать 30 товаров в корзину | Код читается целиком. Позиции и фокус обрабатываются без потерь |
| P06 | Проверить весы с клавиатурным выводом 0,375 kg и 375 g, затем оформить весовую позицию | Оба ввода дают 0,375 кг. Неверная единица отклоняется. Иные протоколы весов требуют драйвера или адаптера |
| P07 | Выбрать тестовый принтер Windows, распечатать чек и вернуть документ на печать из истории | Оба экземпляра сохраняют номер, время, сумму и нефискальную отметку |
| P08 | Отключить принтер после проведения продажи и повторить печать | Продажа проводится один раз. Чек доступен из истории после восстановления принтера |
| P09a | Добавить товар в корзину, отключить сеть и нажать F2 | Диалог оплаты остаётся закрытым, корзина сохранена. После восстановления сети повторное нажатие F2 открывает оплату |
| P09b | Оборвать сеть после фиксации операции на сервере и повторить по исходному ID | Сервер подтверждает одну продажу. Корзина и журнал согласованы |
| P10 | Сделать частичный возврат, затем возврат сверх лимита через администратора | Сервер проверяет лимит. Возврат и движение денег регистрируются один раз |
| P11 | Провести накладную с файлами и проверить отчёты | До проведения остатки не меняются. После проведения отражаются правильные партии и суммы |
| P12 | Проверить русский и узбекский интерфейс при 1366×768, 1280×720, масштабе 125% и 150% | Основные кнопки и подсказки доступны, чек читаем |
| P13 | Проверить резервное копирование, восстановить отдельный тестовый стенд и сверить операции | Выполнены цели восстановления и проверена целостность данных |
| P14 | Удалить программу и проверить пользовательский профиль и конфигурацию | Ярлык и программа удалены. Данные, журналы и KasaPilot.json сохранены |
| P15 | Отложить чек, изменить цену и восстановить его. Изменить цену ещё раз перед F2 | Кассир видит предупреждение и новую сумму. Повторная переоценка блокирует F2. После новой сверки продажа списывает остаток и закрывает отложенный чек |
| P16 | Проверить принтер по умолчанию, затем убрать назначение и повторить проверку | Статус на главном экране соответствует последней проверке Windows. Физическую печать проверяют отдельно |
| P17 | Включить 2+1, продать три штуки, изменить цену и провести два возврата | Итог продажи учитывает одну бесплатную единицу. Сумма возвратов равна исходной оплате |
| P18 | Уценить одну из двух партий, ввести общий код и затем код LOT | Общий код предлагает выбор с ценами. Код LOT выбирает одну партию. Цена и остаток второй партии сохраняются |
| P19 | Ввести код LOT просроченной партии | Касса блокирует продажу этой партии и сохраняет корзину |

Перед фиксацией результатов подтвердите с ответственным фактический состав оборудования и регламент инцидентов. Реальные продажи и фискализация относятся к отдельному согласованию по ТЗ.

## Подпись и контроль состава

На Windows используйте Windows SDK SignTool и NSIS. Скрипт source/installer/Build-SignedPilot.ps1 принимает копию папки portable, отпечаток сертификата владельца из хранилища Windows, HTTPS-адрес службы отметки времени и новый путь установщика. Скрипт подписывает исполняемый файл, собирает и подписывает установщик, проверяет обе подписи и выводит SHA-256. Закрытый ключ остаётся в хранилище владельца.

Пример запуска из PowerShell с уже настроенным сертификатом:

    .\source\installer\Build-SignedPilot.ps1 -Payload .\portable -CertificateThumbprint <отпечаток> -TimestampUrl <HTTPS-адрес-службы> -Output .\KassaSetup-Signed.exe

Описания входа приведены в RFC 8252 и RFC 7636 на www.rfc-editor.org. Инструкция SignTool доступна на learn.microsoft.com/windows/win32/seccrypto/signtool.
